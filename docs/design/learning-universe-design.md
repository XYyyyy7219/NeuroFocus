# 星图方案比较

|方案|视觉与含义|交互|性能|实施和扩展|
|---|---|---|---|---|
|连续力导向知识网|有机网状，边须有真实关系|可拖动，新增节点易改变旧位置|持续模拟，稠密时难读|需布局持久化、碰撞和关系编辑|
|按月轨道年轮|按时间看演化清楚，科目混杂|时间定位快，主题回顾需筛选|静态布局，开销小|易加入时间刻度，难表达主题层次|
|逐层学科星系|学科、主题、活动各占一层，学习时长和日志各有独立视觉标记|点击深入，列表或搜索直接定位|仅实例化当前层对象，静止时无动画循环|用 Qt Graphics View 的索引和变换，便携包沿用 QtWidgets|

选用第三种，将第二种的时间含义保留给日期滑块。相同标签 ID 稳定，活动排列基准来自全部历史，筛选不重新排位。主题以学科内的可选文字归组；相同主题的活动可表示明确的延续，未命名活动不推断关系。暂缓真实三维视角、自由编辑知识连线和长期跨应用引擎。Qt Quick 会带来第二套 UI 和资源管线，WebGL 需浏览器运行时，纯 QPainter 则需自建场景查询。

恒星同步按活动键更新已有图元。主题内选中恒星时只连到前、后同主题的活动，便于沿着自己记录的主题回顾。回放用活动发生日期控制可见性，日志与科目名称采用当前文字；不会重演每次改笔记的历史状态。主动更改主题会影响相关组的位置。

当前档案在打开时读取全部片段，并在数据库有新写入时重算活动投影。场景则只处理当前层。后续若多年数据使冷启动变慢，可按周期失效缓存并保持现有稳定键，先测量真实数据规模再实施。
